# Real-model decode profile and numerical localization

The Nsight Systems capture covers thirty context-1024, batch-one BF16 native decodes after five warmups, with pre/post numerical checks. NVTX marks reset and decode enqueue separately. Only the application’s cudaProfilerStart/Stop interval is captured; loading/prefill/reference preparation are excluded. This is diagnostic tracing, not an uninstrumented latency benchmark. Raw process status, source/binary metadata and CSV statistics are retained in `native-model-trace-*`; the local trace/SQLite hashes are in `native-model-trace-artifacts.json`.

The persistent megakernel accounts for 99.7% of traced CUDA **kernel execution time**, averaging 14.430 ms in this instrumented run. Argmax averages 0.0355 ms; the embedding indexing kernel averages 0.00295 ms. Memory-copy activity and CPU enqueue gaps are separate from this percentage. The trace supports focusing on the persistent kernel, but does not establish whether its time is DRAM bandwidth, scheduling, TMA or barrier dominated. Nsight Compute hardware counters remain unavailable under current permissions; worker-local timing is the next profiling step.

Temporal step-10 diagnostics maintain independent native/reference KV histories while feeding identical reference tokens. The matched-capacity probe uses the same context+101 cache capacity as the hundred-step qualification. It reproduces logit NRMSE 3.0331% and hidden NRMSE 2.5565%, both outside the unchanged gates, with matching greedy tokens. Isolated layer prefixes start from reference hidden inputs. With reference past KV, worst partial-attention NRMSE is 0.0377%; using native past KV raises it to about 1.84%. This localizes an important part of the deviation to accumulated KV history, rather than a large error from a single isolated attention operation. It does not prove that attention is the initial source: projection/activation differences still accumulate into the cache.

Raw diagnostics: `temporal-drift-step10-matched-capacity.json` (original matching horizon), and `temporal-drift-step10.json` (initial shorter-cache probe). The layer-prefix comparisons are diagnostic, not replacements for full temporal gates. No accuracy tolerance was relaxed.

The existing optional internal timing path needs an instrumentation audit before calibration: generic event IDs can be written by multiple lanes/warps, and each thread's clock64 origin is local. Use race-free stores and paired durations from the same warp; do not subtract absolute timestamps across SMs or different thread origins. Timing remains disabled in the qualified baseline.
