# Device ready dispatch for the native Llama VM

`configs/thor/ready-queue.json` / `MK_READY_QUEUE=1` selects a device-side ready queue for the existing full Llama instruction DAG. This is distinct from the earlier standalone vector-DAG probe: the controller now dispatches all native Llama opcodes used by the model, using the existing loader/consumer/storer implementations and page protocol. The static per-worker queues remain the default.

The host stores one shared `[1,N,32]` instruction table, outgoing CSR offsets/children and initial indegrees. The controller claims only tasks with zero remaining dependencies. Device-scope acquire/release atomics protect head/tail, published slots, indegrees, visit counts and completion. A tail reservation does not make an unwritten slot consumable: consumers acquire its nonnegative task ID before claiming it with a head CAS. A successful claim verifies zero remaining dependencies and increments a visit count that traps on a duplicate claim.

Each task uses the ordinary instruction-slot/page phases, indexed by the worker's local execution count rather than the global task ID. Execution roles join at the non-aligned counted instruction barrier. The controller waits for every execution thread's release-arrival at instruction completion, invalidates the completed task's semaphores, then publishes child readiness through acq_rel indegree RMWs. Those RMWs chain preceding producers' publication; a child's acquire observes completed parent writes before its own instruction is released to the execution roles. Native opcodes still complete their existing global/TMA stores and counter publication. The first implementation disables controller prefetch and executes one task at a time per worker.

All CTAs must be occupancy-admitted in a cooperative single-CTA-per-SM grid. Workspace initialization precedes a grid synchronization; root publication precedes another grid synchronization. Plain root-indegree reads therefore do not race with task completion updates. A controller can wait on an unpublished reserved slot only while its publisher is concurrently resident. No dispatched task waits for a DAG producer left unclaimed in the queue: the host audits the actual native barrier fan-ins, not just generic graph acyclicity. Down-projection retains its full up/gate-wave dependency. The supported full-model DAG uses the existing skip-attention-reduction path with one partition per KV head; other model/partition DAGs are rejected by this audit.

Termination requires the completed count to reach N, rather than merely claiming all tasks. Each controller then publishes an internal -1 instruction, which execution roles acknowledge through the same completion protocol before leaving. That sentinel is never an input opcode. A worker executes at most N distinct tasks plus the sentinel. The parent process watchdog remains required for whole-run failures; optional global polling cycle watchdogs remain available through the existing debug define.

The packed mutable layout is `head, tail, completed, slots[N], pending[N], visits[N]`. Every kernel launch resets it inside the timed runtime. Model checks require all counters to equal N, published slots to be a permutation of task IDs, every indegree to be zero and every visit to equal one. CSR construction rejects missing/duplicate producers, duplicate tasks, cycles, unsupported opcodes and int32 indexing overflow. The full-model audit additionally verifies exact QKV/head/output coverage and all native counter producers for attention, O projection, up/gate, down projection and LM head. Worker-count changes invalidate the task representation as well as static queues.

For the tested Llama-3.2-1B-Instruct configuration, the graph has 3,156 physical tasks and 70,784 dependency edges. Instruction storage is 403,968 bytes, immutable CSR/indegrees 308,388 bytes and mutable workspace 37,884 bytes. The prototype additionally reserves 32,327,680 bytes of worst-case timing capacity for `[workers,N+1,128]`; timing is disabled and the ready controller rejects timing-enabled builds. This unused capacity is a prototype memory overhead, not an optimized memory footprint.

Validation from `model-ready-qualified/`:

- Eighteen empty/chain/fan/random NoOp graphs cover 0/1/2/3/17/257 tasks, shuffled table order, slot reuse and unchanged activations. All eighteen pass separately under synccheck, memcheck and racecheck: 54 sanitizer fixture cases.
- The complete Llama decode separately passes all three sanitizer tools, with zero errors/hazards. Task coverage is checked alongside model outputs.
- All 45 frozen-input checks pass across contexts 128/1024/8192, seeds 1/2/3 and five repeats per pair, including exact task/dependency coverage on every run.
- Three independently loaded performance batches per variant pass all 270 timed checks. Ready coverage is checked after every measured ready sample.
- The hundred-step independent-native-cache/math-reference test completes but **fails** steps 10/11/21, exactly matching the earlier SIMT baseline: worst logit NRMSE 3.08516%, hidden 2.55646%, all one hundred greedy tokens agree. This numerical failure is preserved; progress/coverage checks do not waive it.

The cohort observes p50 14.386 ms for ordinary static queues, 14.340 ms for static queues with the same execution-role join, and 18.706 ms for ready dispatch. The ready prototype is approximately 30% slower in this uncontrolled shared-load cohort. The joined control retains static controller prefetch, while the ready controller serializes dispatch and adds CSR atomics and state initialization; the experiment does not isolate those costs. This is same-cache context-1024 replay, not autoregressive generation. See [table, CSV and CDF](benchmark-model-ready.md).

Recommendation: retain ready dispatch as an opt-in research implementation and preserve the static default. The first design proves integration/progress on the tested cases but does not improve latency. Dense fan-in bookkeeping and serialized controller work are candidates for separate measured refinements; they are not established bottleneck percentages. Native activation retention is not implemented by this queue.

Reproduction: source `tools/thor/env.sh`, build the chosen config using the recorded compiler command, set `THOR_CONFIG` and `THOR_BINARY_DIR`, then use the standard `tools.thor.model_bench:make_adapter` benchmark factory. Ready dispatch selects device FIFO; the default scheduler field is retained for configuration compatibility, and non-default static scheduler overrides are rejected. Non-native ready adapters are rejected before loading weights. Use `python -m tools.experiments.model_ready_probe --output local/ready-noops.json` for the eighteen VM cases. A control with `serial_instruction_handoff=true, ready_queue=false` keeps the same execution-role join. Regenerate the report with:

```bash
python -m tools.experiments.model_ready_report docs/thor/model-ready-qualified --output docs/thor/benchmark-model-ready.md
```

The Llama native binding now includes two optional ready-buffer descriptors; rebuild extensions after updating the Python interpreter. Static callers receive minimal unused buffers. H100/B200 compile checks pass, and the main Thor static module is refreshed. Data-center hardware execution remains untested. Host validation now runs 58 tests, with one optional GPU test skipped; the native CUDA tests above run separately. Source, binary and process records distinguish the initial pilot from the final qualification.

A follow-up host-only guard patch rejects empty/malformed full-model output ranges, unsupported backend selections and ignored static scheduler overrides. The refreshed static and ready builds each pass five further model checks. Their embedded CUDA `.nv_fatbin` sections are byte-identical to the corresponding comprehensively qualified device images (`model-ready-guard-refresh/device-image-comparison.json`).
