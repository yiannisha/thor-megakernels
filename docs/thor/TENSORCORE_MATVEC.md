# Selectable BF16 warp-MMA matvec on Thor

`configs/thor/tensorcore-matvec.json` / `MK_TENSORCORE_MATVEC=1` enables the existing warp-level BF16 MMA matvec helper on SM110a explicitly. Thor still defines `KITTENS_HOPPER`, not `KITTENS_BLACKWELL`; this helper uses no B200 tensor-memory/TCGEN path. H100 retains its historical SIMT helper and B200 retains its historical MMA helper. The checked binding reports the actual selected matvec backend, and both the model adapter and model-free fixture reject a build/configuration mismatch. The standalone model-check CLI also has `--tensorcore-matvec` and honors `THOR_BINARY_DIR`.

Each consumer warp broadcasts its input vector across sixteen rows, multiplies a BF16 weight tile by its transpose into FP32 accumulators, and extracts the duplicated dot product per output row. The subsequent FP32 sum across consumer warps is unchanged. This duplicates work inside the MMA tile and is a prototype, not an assertion that Tensor Cores are optimal for batch-one GEMV. BF16 storage is unchanged. The configuration requires BF16-rounded normalized inputs, enforced by Python validation and a C++ static assertion, so enabling MMA cannot silently introduce an additional activation-rounding point relative to a float-normalized SIMT configuration.

Initial native compilation succeeds and all twenty model-free matvec tests pass: QKV, O projection, up/gate, down projection and LM head, each at 0/1/4/8 iterations. Zero-iteration cases additionally test repeated instruction-slot/page reuse. These are seeded synthetic inputs, not every rotary/cache branch. The initial context-1024 pilot passes ninety full-model replay checks per backend, with observed medians 11.625 ms SIMT and 11.355 ms MMA. That sequential, shared-load pilot is not a controlled speedup.

Final-source qualification (`tensorcore-matvec-qualified/`) passes memcheck, synccheck and racecheck with zero errors/hazards; the explicit model-check CLI; and all forty-five frozen-input replay checks across contexts 128/1024/8192 and seeds 1/2/3. Worst logit NRMSE is 2.28195%, within the unchanged 3% logit gate; hidden/KV gates remain 2%. The numerical gates also retain their maximum-error check. The earlier SIMT compensated-attention matrix had a lower worst frozen logit error, 1.6819%; the single-case pilot improvement does not generalize to a uniformly better matrix.

The independent-native-cache hundred-step test against the math-attention reference **fails nine steps**: 9/10/11/21/31/32/44/88/99. Worst logit NRMSE is 4.01008%, hidden NRMSE 2.58100%; all one hundred greedy tokens match. This is worse than the earlier SIMT baseline's three failed steps and does not resolve accumulated numerical drift. Failed records remain intact. Matching tokens is not an accuracy waiver.

A second comparison uses three independently loaded batches of thirty checked samples per backend, with five warmups and seeded shuffled order. It passes all 180 timed correctness checks. Pooled medians are 14.435 ms SIMT and 14.343 ms MMA, an observed difference of approximately -0.64%; p99 is 14.801/14.833 ms, respectively. GPU load is uncontrolled, and this particular shuffle put MMA first in all three pairs. These results do not establish a controlled latency or tail improvement. The scopes are same-cache context-1024 replay, not autoregressive generation or vLLM comparison. See [table, CSV and CDF](benchmark-tensorcore-matvec.md).

Both builds use sixteen consumer warps, 640 threads, a static 96-register cap, three input stages, thirteen 16-KiB pages, and one admitted CTA/SM. Static shared memory is 10,384 bytes and dynamic shared memory is 214,015 bytes. Each reports 208 local bytes/thread. Ptxas reports 64/108 bytes of spill stores/loads for SIMT and 72/132 for MMA; these compiler reports are not measured runtime traffic. There is no spill-reduction claim.

Recommendation: retain the mode as an opt-in experiment, keep the existing default, and do not claim a quality-matched generation speedup. The candidate is memory/race/sync checked on the tested model case but fails temporal numerical qualification. More tiling/register tuning would require new evidence rather than assuming the pilot advantage is reproducible.

Reproduction: source `tools/thor/env.sh`, build using the exact command/config in each process record, set `THOR_CONFIG` from the selected JSON and `THOR_BINARY_DIR` to that build. The normal benchmark factory is `tools.thor.model_bench:make_adapter`. Run `tools.thor.teacher_forced --context 1024 --steps 100 --reference-attention math --native-past` for the accumulated-cache check. The standard CLI check needs `--tensorcore-matvec --fp32-downproj --match-torch-bf16-epilogues --compensated-attention` for this mode. Regenerate the report with:

```bash
python -m tools.experiments.matvec_report docs/thor/tensorcore-matvec-qualified --output docs/thor/benchmark-tensorcore-matvec.md
```

Earlier pilot data and final-source data have separate process/source fingerprints. H100/B200 compile checks succeed, and the primary Thor SIMT module is refreshed from the final source. Data-center hardware execution remains untested. The host suite runs 54 tests with one optional GPU test skipped; native GPU checks above ran separately.
